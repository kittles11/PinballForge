# Boss 行为设计方案（P2-1 内容多样化）

> 状态：**已拍板并实现（A+B+C 全做）**，代码落地于 `DataModels`（轮换表/参数）+ `EnemyController`（行为状态机）+ `WaveManager`（亲卫生成）+ `funnelType` 契约链。覆盖自检 `selfcheck-boss-behaviors.ts`（24 项）。
> 实现期两处修订：① 坚盾盾时长 10s→**6s**（自检抓到：10s > 最紧间隔 8s 会让"不叠盾"守卫静默跳过周期、收紧曲线失效；6s 使覆盖率 50%→75% 随章节真实收紧）；② 同屏护栏计数由 `EnemyController.aliveCount` 自维护（import EnemyManager 会构成运行时循环，违反 code-standards 规则 4）。
>
> 设计约束（来自模型与 game-design 原则）：
> 1. **行为必须咬住玩家核心动词**（瞄准 / 选漏斗 / 构筑），只加血量的 Boss 是数值墙不是内容；
> 2. **禁止硬检查造成不可赢**：基线牌库从第 5 章起余量已为负（需 DPS 257 vs 基线 194），Boss 机制只能"软惩罚"（减伤/节奏损失），不能全免疫；
> 3. **可读性优先**（可供性 + 预备动作）：每个行为生效前必须有可见预告，Boss 施法期间**定身 0.8~1s**——既是读招窗口，也是对 DPS 损失的补偿；
> 4. **Hick 定律**：单 Boss 同时至多 2 个行为（狂暴回复 + 1 个特色行为），50 章靠轮换与参数缩放产生变化，不靠堆技能。

## 方案 A：破阵坚盾 —— 漏斗选择检查

**机制**：Boss 每 12s（后期缩至 8s）举盾 3 层（复用护盾弧 + 定身 0.8s 预告）。举盾期间**所有伤害 ×0.5**（软减伤，非免疫）；**重炮槽（红）入槽的炮弹每发剥 1 层、熔岩弹剥 2 层**（已拍板：给熔岩流派 Boss 应答位，两通道可叠加）。3 层剥光或 **6s** 后盾碎，恢复正常（实现期修订：盾时长必须短于最紧举盾间隔 8s，否则"不叠盾"守卫静默跳过周期、收紧曲线失效——自检抓到）。

**玩家决策**：盾周期内把球往红槽引——金币槽的 +20 要忍痛放弃（贪婪税）。漏斗选择从"顺手"变成"每 12 秒一次的真决策"。

**数值影响**（实现后校准：盾时长 6s / 间隔 12→8s ⇒ **盾覆盖率上限 50%→75%**，非设计初稿假设的全程覆盖；`tools/balance-double-halve.ts` Boss 行为等效表实测）：
- 应对（剥盾提前一半覆盖率）：等效血量 ≈ ×1.14~×1.25；
- 无视（吃满覆盖率）：等效血量 ≈ ×1.33~×1.5——比初稿估的 ×2.0 温和，机制强度靠**金币机会成本**（盾窗口放弃金槽 40~60 金/周期）补足；
- 若实机反馈"无视盾无痛"，调参旋钮按序：`bulwarkDamageMult` 0.5→0.4 → `bulwarkLayers` 3→4 → 覆盖率上限随间隔收紧自然上升。

**实现成本**：中。需要 `FIRE_TURRET` 载荷补 `funnelType` 字段（OrbController 发射端已有该信息 → TurretController 透传 → takeDamage 判定剥盾），EventBus 契约动一处（可选字段，向后兼容）；护盾视觉/跳字全复用。涉及：`EventBus.ts`、`OrbController.ts`、`TurretController.ts`、`EnemyController.ts`。

**风险**：payload 改动面 3 文件；新玩家第一次遇到可能困惑（用定身预告 + 盾弧 + 「🛡️ 格挡」跳字三连缓解，铁甲怪在第 1 章就教过护盾语义——**已学技能复用**）。

## 方案 B：君王诏令 —— 索敌与 AoE 检查

**机制**：Boss 每 8s 诏令召唤 2 只亲卫（普通怪外观 + 金边染色，HP = Boss 最大生命 12%，移速 ×1.3）。召唤前摇 1s 定身鼓腮（预告）。亲卫出生在 Boss 前方一格 → **炮塔最前索敌自动被抢**，Boss 进入"真身无敌"窗口直到亲卫清掉。

**玩家决策**：三选一——① 急冻流全场冰封按住所有目标；② 雷球散射多目标覆盖；③ 单发重炮硬啃亲卫保节奏。纯单体构筑（重炮单球）在这里付出真实代价。

**数值影响**：
- 每周期额外承伤 2×12% = Boss 等效血量 ×1.24（含亲卫行军时间则更高，约 ×1.3）；
- 与狂暴回复叠加：无行为 ×1.2 → B 行为 ≈ ×1.5，10-10 需构筑 DPS 从 ×2.6 → ×3.3；
- 亲卫本身会撞线（20 伤/秒 ×2 只）——不管它们就是双输，**压力真实但不致死**（12% HP 亲卫一发普通球就能带走大半）。

**实现成本**：**低**。Boss 分支加一个 `schedule(summon, 8)`，内部直接 `EventBus.emit(ENEMY_SPLIT, {...})`——生成、计数、血条、死亡结算全部走史莱姆已验证的管线。涉及：`EnemyController.ts` 一个文件。

**风险**：召唤物叠加失控（史莱姆分裂 + Boss 诏令同屏小怪过多）→ 同屏敌人软上限 10，超限则诏令静默跳过（护栏一行代码）。

## 方案 C：破绽时刻 —— 时机检查（正反馈型）

**机制**：Boss 每 10s 露出 3s 破绽：提前 1s 身体闪烁 + 蓄力音（预备），窗口内身体泛红核发光、**受到伤害 ×2**。窗口外无惩罚。

**玩家决策**：把手里的球攒到窗口内连发——把"发射节奏"从被动冷却变成主动资源管理。Balatro 式"憋大招"爽感，与结算大字反馈同脉。

**数值影响**：
- 完美应对：DPS ×(1 + 30%×100%) ≈ **×1.3**（玩家白赚，抵消 A/B 的部分压力）；
- 不应对：×1.0 零惩罚——**纯正向检查**，适合做教学 Boss 行为；
- 与出手机隔联动：模型显示 shotInterval 是最大杠杆（摆幅 411%），C 行为等于给"节奏"这个隐藏变量一个显性奖励面。

**实现成本**：**低**。计时器 + 现有 tween 脉冲 + `takeDamage` 入口一个倍率分支。涉及：`EnemyController.ts` 一个文件。

**风险**：无惩罚 = 无压力，单独用偏软；定位是第 2 章教学位与 A/B 的缓冲垫。
